# Методология бенчмарка

## Цель

Честно сравнить SQL и Cypher на одной задаче: поиск кратчайшего пути.

## Что сравниваем

| Вариант | Описание |
|---|---|
| **SQL naive** | Recursive CTE без pruning (как в первой версии) |
| **SQL optimized** | Recursive CTE с pruning по upper bound |
| **pgRouting** | Нативный Dijkstra на C в PostgreSQL |
| **Neo4j** | `apoc.algo.dijkstra` |

## Что НЕ сравниваем

Честно говорим, чего в бенчмарке нет:

- ❌ Materialized views в PostgreSQL
- ❌ Partitioning таблицы roads
- ❌ Кэширование результатов
- ❌ Кластер Neo4j (single-node)
- ❌ Реальные пробки (синтетические данные)

**Вывод:** цифры — нижняя граница для SQL и верхняя для Neo4j. Реальный разрыв может быть меньше. Но даже так — он на порядки.

## Данные

- Генератор использует **одинаковый seed (42)** для Neo4j и PostgreSQL
- Одинаковое количество городов, дорог, складов
- Одинаковые веса рёбер
- Сверка: `sql/verify.sql` + `docker/neo4j/verify.cypher`

## Метрики

- **Avg** — среднее по 20 итерациям
- **Min** — лучший результат
- **Max** — худший результат
- **Speedup** — отношение avg SQL к avg Neo4j

## Как запустить

```bash
# 1. Малый граф (1000 городов)
docker-compose --profile generator run --rm generator
bash scripts/run-benchmark.sh

# 2. Большой граф (100 000 городов)
NUM_CITIES=100000 NUM_ROADS=500000 \
  docker-compose --profile generator run --rm generator

Результаты в output/benchmark.csv и output/benchmark.png.

# Интеграция 1С и Neo4j

## Три способа

| Способ | Плюсы | Минусы |
|---|---|---|
| **HTTP-прокси** | 1С умеет HTTP «из коробки» | Дополнительный сервис |
| **Bolt напрямую** | Быстрее HTTP | Нужна внешняя компонента |
| **Промежуточный сервис** | Гибкость | Сложнее поддержка |

В демо — **HTTP-прокси**: проще всего для 1С.

## HTTP-прокси: базовый вызов

```bsl
// 1С: отправка запроса в прокси
Функция КратчайшийПуть(Откуда, Куда)
    HTTPСоединение = Новый HTTPСоединение("localhost", 8080);
    Запрос = Новый HTTPЗапрос("/api/v1/graph/shortest-path", "POST");
    
    Тело = Новый Структура("from,to", Откуда, Куда);
    Запрос.УстановитьТелоИзСтроки(СериализоватьJSON(Тело));
    
    Ответ = HTTPСоединение.ВызватьHTTPМетод(Запрос);
    
    Если Ответ.КодСостояния <> 200 Тогда
        ВызватьИсключение "Прокси вернул " + Ответ.КодСостояния;
    КонецЕсли;
    
    Результат = Новый ЧтениеJSON;
    Результат.УстановитьСтроку(Ответ.ПолучитьТелоКакСтроку());
    Возврат ПрочитатьJSON(Результат);
КонецФункции
bash scripts/run-benchmark.sh

Синхронизация: проведение документа

// 1С: при проведении документа «Заказ на доставку»
Процедура ОбработкаПроведения(Отказ, Режим)
    // ... стандартная проводка в PostgreSQL ...
    
    // Публикация события в RabbitMQ
    Событие = Новый Структура;
    Событие.Вставить("action", "new_road");
    Событие.Вставить("entity", Новый Структура);
    Событие.entity.Вставить("from", ГородОтправления);
    Событие.entity.Вставить("to", ГородНазначения);

КонецПроцедуры

Обработчик на стороне прокси читает очередь и обновляет граф:

# Обработчик RabbitMQ → Neo4j
def handle_message(ch, method, properties, body):
    event = json.loads(body)
    requests.post("http://proxy:8080/api/v1/graph/update", json=event)

Идемпотентность
Все операции update идемпотентны:

MERGE (a)-[r:ROAD]->(b) SET r += $props — не создаёт дубли

MERGE (w)-[s:STOCKS]->(p) SET s.quantity = $q — обновляет

Повторная отправка того же события не ломает граф.

Eventual consistency
Граф обновляется асинхронно

Возможен рассинхрон на секунды

Reconciliation job раз в час:

Читает sql/verify.sql из PostgreSQL
Читает docker/neo4j/verify.cypher из Neo4j
Сравнивает
При расхождении — полная пересинхронизация
Когда что использовать
Задача	Источник
Документы, проводки, регистры	PostgreSQL
Кратчайший путь	Neo4j
Цепочка поставок	Neo4j
Рекомендации	Neo4j
Отчёты по периодам	PostgreSQL
Агрегаты	PostgreSQL
Правило: если задача про обход связей — Neo4j. Если про агрегаты — PostgreSQL.

# Расчёт экономии

## Исходные данные

- 500 заказов/день
- 50 складов
- 200 машин
- 3 логиста
- 250 рабочих дней

## Источники экономии

### 1. Сокращение времени логистов

**До:** 3 логиста × 1.5 ч/день на ручную корректировку маршрутов  
**После:** 3 × 0.5 ч/день на проверку  
**Час логиста:** 800 руб (с налогами)

```
3 × 1.0 ч × 800 руб × 250 дней = 600 000 руб/год
```

### 2. Сокращение ошибок доставки

**До:** 0.5% заказов с ошибкой  
**После:** 0.1%  
**Штраф за ошибку:** 3000 руб

```
0.004 × 500 × 250 × 3000 = 1 500 000 руб/год
```

### 3. Высвобождение FTE

**До:** 2 FTE заняты ручной оптимизацией  
**После:** переводятся на другие задачи  
**Стоимость FTE:** 1 200 000 руб/год

```
2 × 1 200 000 = 2 400 000 руб/год
```

### 4. Оптимизация пробега (консервативно)

**До:** средний пробег 120 км/заказ  
**После:** 115 км/заказ (4% сокращение)  
**Стоимость км:** 25 руб

```
500 × 5 км × 25 руб × 250 = 15 625 000 руб/год
```

**НО:** реалистично оптимизируется 30% заказов (остальные — фиксированные маршруты).  
Реальное сокращение — 1.2%, не 4%.

```
500 × 1.5 км × 25 руб × 250 = 4 687 500 руб/год
```

| Источник | Сумма, руб/год |

| **Итого** | **~9 200 000** |

# Типовые проблемы

## Neo4j не стартует

**Симптом:** `docker-compose up` падает, Neo4j недоступен.

**Решение:**

```bash
# Проверить логи
docker-compose logs neo4j

# Убедиться, что порты свободны
lsof -i :7474
lsof -i :7687

# Пересоздать volume (осторожно — потеря данных)
docker-compose down -v
docker-compose up -d
```

## APOC не загружается

**Симптом:** `apoc.algo.dijkstra` не найден.

**Решение:**

```bash
# Проверить, что плагин установлен
docker-compose exec neo4j cypher-shell -u neo4j -p password \
  "RETURN apoc.version();"

# Если ошибка — проверить docker-compose.yml:
# NEO4J_PLUGINS: '["apoc"]'
# NEO4J_dbms_security_procedures_unrestricted: apoc.*
```

## Кириллица превращается в кракозябры

**Симптом:** «Москва» отображается как «РњРѕСЃРєРІР°».

**Решение (Windows):**

```powershell
$env:PGCLIENTENCODING = "UTF8"
```

**Решение (Linux/Mac):**

```bash
export PGCLIENTENCODING=UTF8
export LANG=ru_RU.UTF-8
```

## Бенчмарк показывает нереалистичные цифры

**Симптом:** SQL выполняется за миллисекунды там, где ожидались минуты.

**Причины:**
1. Мало данных — проверьте `SELECT COUNT(*) FROM roads;`
2. Нет `ANALYZE` — выполните `ANALYZE;`
3. Планировщик выбрал хороший план — это нормально на малых объёмах

**Решение:**

```sql
-- Проверить статистику
SELECT relname, n_live_tup FROM pg_stat_user_tables;

-- Обновить
ANALYZE;

-- Посмотреть план
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM shortest_path_sql(1, 4);
```

## Рассинхрон Neo4j и PostgreSQL

**Симптом:** `verify.sql` и `verify.cypher` показывают разное количество узлов.

**Решение:**

# 1. Проверить оба источника

```

## Прокси не видит Neo4j

**Симптом:** `/health` возвращает `neo4j: false`.

**Решение:**

```bash
# Проверить сеть Docker
docker-compose exec proxy curl -s http://neo4j:7474

# Проверить переменные окружения
docker-compose exec proxy env | grep NEO4J
```

## Генератор падает на 100k городов

**Симптом:** `MemoryError` или timeout.

**Решение:**

1. Увеличить память Docker: Docker Desktop → Resources → Memory → 8 ГБ
2. Увеличить heap Neo4j: `NEO4J_server_memory_heap_max__size: 4g`
3. Генерировать батчами: `BATCH_SIZE=500`

## Медленный ответ прокси

**Симптом:** запросы занимают >1 сек.

**Причины:**
- Нет индексов в Neo4j — проверьте `SHOW INDEXES;`
- Нет индексов в PostgreSQL — проверьте `\di`
- Мало памяти у Neo4j — увеличьте heap

**Решение:**

```cypher
// Neo4j: проверить индексы
SHOW INDEXES;

// Создать если нет
CREATE INDEX IF NOT EXISTS FOR (c:City) ON (c.name);
```

## Как получить помощь

1. Проверьте логи: `docker-compose logs -f`
2. Проверьте `/health`
3. Запустите `verify.sql` и `verify.cypher`
4. Откройте issue в репозитории
