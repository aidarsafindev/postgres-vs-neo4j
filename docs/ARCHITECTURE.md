    Компоненты
1С (источник истины для учёта)
Документы, регистры, проводки

При проведении документа отправляет событие в RabbitMQ

Читает данные через HTTP-прокси (только для графовых запросов)

HTTP-прокси (Python + Flask)
Принимает JSON от 1С

Транслирует в Cypher / SQL

Возвращает результат

Не хранит состояние

Эндпоинты:

Метод	Путь	Назначение
POST	/api/v1/graph/shortest-path	Кратчайший путь (APOC Dijkstra)
POST	/api/v1/graph/supply-chain	Цепочка поставок
POST	/api/v1/graph/recommendations	Рекомендации
POST	/api/v1/graph/update	Обновление графа
POST	/api/v1/benchmark/sql	Тот же запрос на SQL
GET	/health	Проверка
Neo4j (кэш связей)
Хранит только то, что нужно для обхода: города, дороги, склады, товары, рекомендации

Не является источником истины

Обновляется через события от 1С

Индексы: City(name), Warehouse(name), Product(code)

APOC для Dijkstra

PostgreSQL (учёт)
Источник истины

Документы, регистры, проводки

Дублирует графовые данные для сравнения (в демо)

В проде — только учётные данные

Что где хранить
Данные	Neo4j	PostgreSQL
Города	✅	✅
Дороги	✅	✅
Склады	✅	✅
Товары	✅	✅
Остатки	✅ (как свойства рёбер)	✅ (таблица)
Совместные покупки	✅	✅
Документы	❌	✅
Проводки	❌	✅
Регистры	❌	✅
Бухгалтерия	❌	✅
Правило: в Neo4j — только то, что участвует в обходе графа. Всё остальное — в PostgreSQL.

Eventual consistency
Neo4j обновляется асинхронно

Возможен рассинхрон на секунды

Reconciliation job раз в час сверяет данные

При критичных расхождениях — полная пересинхронизация

См. docs/TROUBLESHOOTING.md — что делать при рассинхроне.
